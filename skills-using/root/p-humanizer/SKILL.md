# 去人机味

让对外文字读起来像作者本人写的：删空话和套路，留住事实和作者的语气。下面的模式是检查线索，不是禁词表；一句话没毛病就不动。

## 硬约束（冲突时按顺序）

1. **不添事实**。原文和用户材料里没有的数字、经历、引文、用户评价、性能结论一律不加；不能用编的细节让句子显得具体。缺料时问用户，或在正文外列出「需要补的素材」。
2. **不丢信息、不改确定程度**。否定、条件、范围、时间、归因保持原样；「可能」不写成「确定」，「计划」不写成「已完成」，相关不写成因果。
3. **守住文体和声音**。帖子、随笔保留第一人称和作者的态度；技术说明保留术语和版本；正式文本不硬改口语。有作者样本时学它的句长、用词和标点。
4. **只改真有问题的地方**。不为显得改过而改，不把连贯段落拆成要点。

## 先写再查

自己起草对外文字时：用作者第一人称讲「为什么做、做了什么、哪里还不行」，用具体功能、截图、动图说话，不用形容词堆价值。写完按下表过一遍，再按「交付前核对」查一遍。

## 检查清单

| 类 | 模式 | 改法 |
|---|---|---|
| 铺垫 | 「不是 X，而是 Y」「不仅…更是…」抬语气 | 直接说 Y；真纠正误解时保留 |
| 铺垫 | 「让我们深入看看」「以下是你需要知道的」 | 删，直接进正文 |
| 铺垫 | 格言、伪深度、单句戏剧性收尾 | 换回具体判断，或删 |
| 铺垫 | 跟假想敌辩论（「不要误会，我不是…」） | 删，只留真实的限制和反对意见 |
| 节奏 | 硬凑三项排比、四字词排比（稳定可靠、快速响应…） | 只留有独立信息的项，不补项 |
| 节奏 | 连续同一主语开头、破折号制造悬念 | 合并或改成普通句 |
| 节奏 | 限定词叠加（也许可能会） | 压成一层，保留真实的不确定 |
| 拔高 | 赋能、至关重要、无缝、闭环、彰显、助力、全方位 | 空泛时换成具体说法；术语照留 |
| 拔高 | 「标志着新时代」「堪称梦想天堂」、句尾补一句意义 | 删套话，留事实 |
| 拔高 | 「专家认为」「业内普遍」无来源 | 给出来源，或保留不确定，不改成自己的断言 |
| 排版 | 装饰性粗体、emoji 小标题、标题党 | 去掉；粗体只给真正要扫读的词 |
| 客服腔 | 「好问题！」「希望对您有帮助」「如有疑问欢迎」 | 删 |
| 残留 | 首句复读标题、谈论上一稿（「这段是刚补充的」） | 删 |
| 中文 | 层叠的「的」、「进行＋动词」、被字句堆叠 | 拆短，改主动，「进行测试」→「测试」 |
| 中文 | 「随着…的发展」开头、「总而言之，让我们拭目以待」收尾 | 删，从事实开始，在事实处结束 |

## 交付前核对

- 每个具体信息都能在原文或用户材料里找到；找不到就撤回。
- 否定、限定、时间、范围、归因和作者立场都还在。
- 列表和排比改完没丢项，也没多出新项。
- 代码、命令、路径、链接、版本号原样保留。
- 交付最终稿即可，不附模式命中清单或自评分，除非用户要。
