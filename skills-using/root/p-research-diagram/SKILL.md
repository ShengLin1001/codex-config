# 科研架构图 / 技术路线图

## 触发条件

只在用户显式调用时执行：Claude Code 输入 `/p-research-diagram`，Codex 写 `$p-research-diagram`。
依赖 PowerPoint（COM 导出 PNG）和 officecli，仅 Windows。

产物是一份 `.pptx`（唯一源文件，全是 PowerPoint 原生形状加示意图，用户可以直接拖动、改字），
外加用 PowerPoint 导出的高分辨率 PNG。形状用 officecli 生成和修改（先加载 `officecli` skill）。

不用 drawio/mermaid：它们只能排出等宽方框网格，做不出骨架造型、色带分区和块箭头，
成品就是“流程图”而不是“架构图”。

## 1. 先理逻辑，定主次，再选骨架

从正文抽出：总题（一句）、研究板块（2–4 个）、板块间关系（递进 / 数据传递 / 尺度跨越）、方法与尺度。
名词、数值、方法名只取自源文件，不补写。

**主次**是评价路线图的第一标准。把 N 个板块 × M 条主线铺成等大网格（房屋 + 3×3 矩阵），
每格同样大小、同样颜色，会被评价为“没有主次、不够突出”。先找出主线（如“相变机制 → 强韧化”两个阶段），再分层表达：

1. 总题通栏：全图唯一的暖色条。
2. 阶段容器：每个阶段一个大框，用不同色相区分；阶段之间用一组双层折线箭头（︾）连接。
3. 行标签：每个研究板块一行，标签加粗，用阶段色粗边框。
4. 链条框：每行 3 个步骤框，用小块箭头串起，常规字重。
5. 示意图：每行右侧一张该板块的结构或样品图，见第 2 节。

按逻辑选骨架，默认用第一种：

| 骨架 | 适合的逻辑 | 造型 |
|---|---|---|
| **分级容器链条型**（默认） | 开题、答辩：板块分属 1–2 个阶段，每个板块一条研究链 | 总题通栏 → 阶段容器（右上角标方法与尺度）→ 每行“行标签 → 3 框链 → 示意图”；阶段间双层折线箭头 |
| 分块容器型 | 每个研究内容内分实验 / 理论两栏 | 虚线容器 + 标题条 + 子栏短框；底部“研究目标”通栏 |
| 房屋 + 矩阵型 | 用户明确要“板块 × 主线”交叉表 | 屋顶＝总题，横梁＝尺度跨越，列＝板块，行带＝主线；容易缺主次，不作首选 |
| 胶囊型 | 输入 → 处理 → 输出，两端呼应 | 上下通栏 + 左右竖条 + 中部 2–3 面板 |
| 阀门型 | 两个子系统经一个核心机制耦合 | 左右两栏 + 中央三圆/三角机制 |
| 圆环型 | 迭代闭环、循环优化 | 中心目标 + 首尾相接的弧形箭头 |
| 罗盘型 / 折纸型 | 一个核心向多维展开 / 多维汇聚一个目标 | 同心环分扇区 / 四瓣围绕中心 |
| 漏斗型 | 多源证据汇聚到一个结论 | 宽口 → 窄底箭头 |

用户给了参照图时走「参照图模式」：保留它的骨架、层级和图文比例，只把内容映射进去，
不重新设计；放不下就压缩文字，不改结构。

## 2. 版式规格

- **尺寸**：默认 16:9 汇报尺寸 33.867 × 19.05 cm（960 × 540 pt），与组会、答辩 PPT 一致，答辩时直接复制。
  插入 Word（正文宽 14.6 cm）时整体缩放约 0.43，字号按这个比例估算 Word 中的实际大小。
  只有用户明确说只给 Word 用时，才把幻灯片设成成品尺寸。
- **字号**（16:9）：总题 28 pt，阶段标题 22 pt，行标签 20 pt，框内 18 pt，方法与尺度标注 ≥ 16 pt
  （缩放进 Word 后约 12 / 9.5 / 8.6 / 7.8 / 6.9 pt）。放不下就缩短，不往下压字号。
  估宽：汉字 ≈ 1 × 字号，西文和数字 ≈ 0.6 × 字号（雅黑粗体更宽）。
- **文字量**：这是路线图最常见的毛病。
  - 每个框只写一个名词短语，≤ 2 行、每行 ≤ 7 字；整框同一字号、字重，不分“小标题 + 小字说明”两级；细节留给正文。
  - 短语写到“模型 / 机制 / 规律”这一层，如“四阶连续介质弹性模型”。不要只写算出的量（如“二至四阶弹性常数”）、
    测试手段（如“拉伸与纳米压痕”），也不要写成结论式的偏正短语（如“最低能垒相变路径”）。
  - 标题都是短名词短语：总题 ≤ 16 字，不写“A、B 与 C”式并列长标题；阶段标题 ≤ 14 字；
    行标签 2 行 × ≤ 6 字（对象 + 内容，如“超薄金膜 / 相变机制”）。
  - 不加“研究板块”“预期成果”这类位置自明的标签，不单列方法栏或横梁：方法和尺度写在阶段标题右侧，
    尺度用体系原子数最直观（如“第一性原理 · 百原子”“机器学习势 · 百万原子”，数量级取自正文）；
    只表达尺寸跨尺度，不加温度（0 K / 有限温度）等第二维度。
- **字体**：主题字体（body/heading 的 latin 和 ea）都设成 `Microsoft YaHei`，形状不逐个写字体。
  文本形状设 `lineSpacing=1x`、`spaceBefore=0pt`，否则母版的 10 pt 段前距会把两行字推偏。
- **配色与立体感**：明亮渐变 + 立体风格，各骨架通用（`house-matrix.py` 仍是早期扁平配色，用时照此换）。
  - 总题：暖色渐变 `#FBE5D6→#F8CBAD`，深棕字 `#843C0C`，与冷色的阶段容器拉开。
  - 阶段容器：自上而下渐变，蓝 `#DEEBF7→#BDD7EE`、绿 `#E2F0D9→#A9D18E`；总题和容器都加 0.75 pt 黑边、下投影和顶部斜面。
  - 链条内衬取容器渐变的深端色，不加边框，只加斜面和 1 pt 柔边，靠立体边缘与容器区分。
  - 行标签、链条框白底圆角，1.5 pt 阶段色边（蓝 `#2F5597`、绿 `#70AD47`）；标签字蓝 `#00448D`、绿 `#407523`。
  - 链内小箭头用阶段深色实心加投影；阶段间的双层折线箭头上层蓝 `#8FAADC`、下层绿 `#70AD47`，把两个阶段的色相接起来。
  - 同一阶段内的行不另配色相，色相只用来区分阶段。
  - officecli 写法：`gradient=DEEBF7-BDD7EE-90`（90 表示自上而下；多段写 `CBE5FD@0-A5CDB0@54-70AD47@100-90`）、
    `shadow=000000-4-90-3-40`、`bevel=circle`、`lighting=threePt`、`softEdge=1pt`。
- **字重**：粗体只给总题、阶段标题、行标签；链条框常规字重。
- **箭头**：链内用小块箭头（`rightArrow`），尺寸统一；不混用虚线或细线箭头，不画反向的验证、反馈箭头；箭头不标字、不加图例。
  阶段之间用双层折线箭头（两个 `chevron` 转 90° 叠放，加投影和斜面），不用粗块箭头、宽幅倒三角或全宽承接带：
  它轻、留白多。下层尖端只碰下方容器边框，不压阶段标题。
- **示意图**是图“突出”的关键，每行右侧放一张：
  - 优先用本人的工作：已发表或在投稿件的结构图（如“基底引入面内应变”这类机制示意图）、组会 pptx 里的图（解压 `ppt/media`）。可以派 subagent 去项目目录找候选。
  - 合作者的实验图（如 HRTEM）用户点名时可以放，交付时提醒图题注明“实验对照 / 合作课题组提供”；引用文献图要注明出处，最好重画。
  - 稿件组图只截一个子图；横向排列的“初态 → 末态”在行内放不下时，拆开改成竖向堆叠，箭头随之旋转。
  - 找不到合适的图时，用 PIL / matplotlib 渲染简单的原子示意图，配色沿用项目里已有的约定（如 CNA 着色：绿 FCC、红 HCP），交付时说明这是示意图。
  - 示意图白底转透明（只清与边缘连通的白色，`get_transparent` 已处理），不加框，在行高内等比放到最大，直接放在容器浅底上。
  - 同一阶段的几行讲同一件事时，可以只放一张图跨行放大（如“基底引入面内应变”跨普适、薄膜两行）；放大后查图的边缘有没有伸出容器边框。
  - 照片（HRTEM）不转透明：取放大子图而非全视场（缩小后全视场只剩灰色纹理），百分位拉伸对比度；
    FCC / HCP 两张并排对比，下方加可编辑文本框标注，整体离容器边框留出余量。
- **图标**：行标签和阶段标题不加小图标；对象的样子靠示意图表达。

officecli 要点（属性名查 `officecli help pptx shape`）：

- 每个形状都起有含义的 `name`（如 `卡片-普适-2`），后续修改用 `shape[@name=…]` 定位。
- 多段文字用真换行符 `\n`（字面量 `\\n` 有时不拆段）；单段格式用 `/p[N]` 设置；文本形状都设 `autoFit=none`。
- `roundRect` 圆角半径 = min(w, h) × adj / 100000。图片用 `--type picture --prop src=<path>`。虚线框写 `lineDash=dash`，不能写进 `line`。
- 旋转形状的 x/y/width/height 指旋转前的框，旋转绕框中心进行，所以转 90° 的 chevron 要把宽高互换后再算位置；`flipV` 会把渐变一起翻转。
- 连接线的外框只能从左上到右下，往右上走的线加 `flipV=true`。`margin` 四值顺序是 l,t,r,b。
- 房屋 + 矩阵型专用：
  - `trapezoid` 屋顶的文字区比外框窄，标题改用叠在上面的文本框。
  - `flowChartOffpageConnector`（下指五边形）的文字区本身只到 80% 高度，`valign=middle` 即可，不要加下边距。
  - 竖排行标签用 `textDirection=eaVert`，只放一段 ≤ 4 字。
- 报 `Unable to remove the file to be replaced` 是文件被杀毒、索引或刚关的 PowerPoint 短暂占用，文件未改动，隔 2 s 重试即可（范例脚本已内置）。

## 3. 生成初稿

新图从范例脚本改起：复制到 scratchpad，改内容和坐标（单位 0.1 mm，辅助函数会换算成 cm 和 pt），然后运行。

- `assets/stage-chain.py`：分级容器链条型（默认），16:9。`-img_dir` 指向放 `row1.png`、`row2.png`… 的目录；不给时放虚线占位框。
- `assets/house-matrix.py`：房屋 + 3×3 矩阵型，成品尺寸 14.6 cm 宽，只在用户要矩阵时用。

```bash
python stage-chain.py -output <dir>/<name>.pptx -img_dir <dir>/img                 # 首次生成
python stage-chain.py -output <dir>/<name>.pptx -img_dir <dir>/img -if_overwrite   # 初稿迭代
```

生成脚本只用于初稿，不随图交付。`assets/*.pptx` 是它们的产物，可用来对照样式。

## 4. 渲染与自查

```bash
python scripts/export_png.py -input <name>.pptx -dpi 200   # 预览
python scripts/export_png.py -input <name>.pptx            # 交付，默认 500 dpi
```

PNG 由 PowerPoint 渲染，与用户编辑时看到的一致；不要用 officecli `view screenshot`（HTML 近似渲染）判断版式。
交付分辨率下把 PNG 切成四块逐块读，逐项查：
- 版式：文字溢出或贴边、元素重叠、箭头指向、对齐、同级元素尺寸一致；
- 主次：是否一眼能看出主线，是否退化成等大格子网格；
- 文字和配色：文字量是否超标（框内两级字、长标题、图例、箭头标字），有没有多余色相，同级形状的渐变、投影和斜面是否一致。

有问题就改脚本重新生成，直到没有问题。

再对照正文核一遍术语：总题与论文题目对应，框内用词与正文一致（正文没有的说法、领域内有专门含义的词会被评审追问）。
需要更高把握时，可派一个 subagent 以评审导师的视角只读审阅，按“学术逻辑 / 视觉排版”给出带优先级的改法，筛过后交用户选。

## 5. 交付后修改

交付后 pptx 是唯一源文件，用户可能已在 PowerPoint 里手改，**不再重跑生成脚本**（不加 `-if_overwrite` 时脚本会拒绝覆盖）。

- 用 officecli 直接改：`officecli set <pptx> '/slide[1]/shape[@name=…]' --prop …`，多处改动用 `batch`。
- 改之前确认用户没在 PowerPoint 里开着这个文件（有 `~$<name>.pptx` 锁文件就等用户保存关闭），否则两边的保存会互相覆盖。
- 改完重新导出 PNG 并检查。

## 6. 交付

- 新版另存为 `<name>-v<N>.pptx/png`，不覆盖构建脚本正在引用的旧图，替换前问用户；用户要求在当前版上直接改时就地改。
- 插入 Word 时宽度取正文宽（14.6 cm），16:9 图约 8.2 cm 高；插入后看图所在页。
- 只想要更多造型灵感时，可让用户在 ChatGPT 网页端用
  [paper-framework-figure-studio-pro](https://github.com/c-narcissus/paper-framework-figure-studio-pro)
  出几张候选图，选中一张后按参照图模式在这里重建成 pptx。
