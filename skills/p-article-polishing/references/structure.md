# 架构与主线

用于写新文章、新章节、整段，或重排已有结构。**动手写正文前先出 outline，交作者确认。**

## 第一步：确定落点

先问清或从材料中提取：

1. **最终结论一句话**：本文最后要让读者接受什么？
2. **支撑它的证据**：有哪几条，各自落在哪个图、表、计算或实验？
3. **稿件类型与目标期刊**：决定章节体例、篇幅、是否需要路线图段。
4. **哪些是本文的新东西，哪些是背景**。

第 1 项答不出来就不要开始写——先和作者把这句结论定下来。缺第 2 项的结论是待确认问题，不是待润色文字。

## 第二步：写 outline

每段一行，四列：

```
节 | 段功能 | 证据落点 | 段尾结论
```

示例（对象抽象为 X/Y/A/B）：

```
Intro   | 建立 X 的重要性         | 文献 [1-4]        | X 的 Y 行为决定 Z
Intro   | 指出空白：机理证据不足   | 文献 [5,6]        | 缺的是 Y 的直接证据，不是现象报道
Intro   | 本文问题与手段           | —                | 用 A+B 回答"Y 是否受 X 控制"
Res 3.1 | 给出基准情形             | Fig. 2(a,b)       | 基准条件下 Y = 数值
Res 3.2 | X 变化时 Y 的响应        | Fig. 3, Table 1   | Y 随 X 单调变化，幅度 A→B
Res 3.3 | 排除竞争解释 C           | Fig. 4(c)         | C 单独不足以解释该幅度
Disc    | 统一机理                 | Fig. 3+4          | Y 的变化来自 X 经由 M
Concl   | 收口                     | —                 | 主线结论 + 一句有边界的意义
```

outline 自检：

- 只读"段尾结论"列，逆序往前推，能不能连成一条通向最终结论的链？断口就是缺的段落。
- 每段的功能唯一吗？承担两个功能的段拆开。
- 有没有段落的证据落点是空的？它要么是必要的背景或过渡，要么该删。
- 有没有证据没被任何段落用到？要么补一段，要么它不属于本文。
- 有没有段落把前面已经排除的解释又当成主因？删掉这条回头路。

## 第三步：章节功能骨架

按需选用，不是填空模板。不凑句数，只保证证据链完整。

| 章节 | 功能序列 |
|---|---|
| Abstract | 对象与问题 → 具体空白 → 本文做了什么 → 最重要的定量结果 → 机理或独立验证 → 一句有边界的意义 |
| Introduction | 背景与代表性证据 → 明确空白 → 本文能回答的问题 → 方法与路线 |
| Methods | 框架或仪器 → 关键参数与近似 → 统一口径 → 可靠性验证 |
| Results（每小节） | 图/panel 定位 → 条件与定量趋势 → 基准或对照 → 与证据强度匹配的解释 → 段尾结论 |
| Discussion | 核心关系 → 多个结果的统一机理 → 与已有工作比较 → 候选来源及其证据强弱 → 限制与待验证部分 → 有边界的综合 |
| Conclusion | 对象与方法 → 按正文顺序概括主结果和关键数字 → 机理或验证结论 → 一句意义 |
| Figure caption | 首句说明整图功能 → 逐 panel 覆盖 → 解释颜色、线型、符号、箭头、插图、统计量 |

分章要点：

- **Introduction**：空白要说清缺的是哪一种——缺报道、缺知识、缺机理、缺实验验证，还是缺测量能力。文献例子要说明其对象、方法或结论与本文问题的关系，不堆作者名单。路线图段只在目标稿需要时写。
- **Methods**：反复使用的方向、基准或条件用一句统一口径交代（`Unless otherwise specified, ...`）。可靠性要有比较量和文献结果，不能只说方法可靠。
- **Results**：小节的组织顺序服从主线。是否给主结果编号、是否在小节末标记主发现，跟随目标稿既有体例。
- **Discussion**：深化、统一并解释正文结果，不重复 Results 的数字。
- **Caption**：图注描述图里有什么，机理讨论留在正文。

## 第四步：按 outline 写正文

逐段写，每段写完对照该行的功能和段尾结论。偏了就改 outline 或改段落，不要让正文和 outline 悄悄分叉。语言层面同时过 SKILL.md 的四条自检，措辞选择见 [language.md](language.md)。

## 重排已有文本

1. 先给**现状 outline**：每段实际在做什么，而不是应该做什么。
2. 标出问题段：功能重复、无证据落点、不推进主线、走回头路、一段承担多个功能。
3. 给出**目标 outline** 和段落层面的移动/合并/删除清单，确认后再动笔改句子。

先改结构再改语言。在错位的段落里润色句子是白做。
