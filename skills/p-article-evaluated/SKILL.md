# P Article Evaluated

审稿前自检：先判断论证是否成立，再看文章有没有把论证组织清楚，最后看英文是否准确自然。**只诊断，不改写**，改写交给 `p-article-polishing`。

判断原则和章节功能骨架见 [references/criteria.md](references/criteria.md)。目标期刊体例、稿件类型和作者约定高于这里的默认规则。

## 边界

可评整稿，也可评摘要、章节、图注或片段。开始时说明实际读到的范围，缺失材料影响的维度记 `Not assessable`。

- 不虚构实验、数据、引用、图表内容或作者意图；不改数据、结论、限定条件、引文键、图表编号、公式、符号、数值、单位。
- "文中没写"不等于"研究没做"——区分报告缺失、证据不足和不可评价。
- 不用个人偏好覆盖全文已统一的术语、时态、拼写、单位、图号体例。
- 不给接收/拒稿/期刊归属结论，不做整稿润色、格式转换、文献管理、投稿操作。

## 路由

- **点名维度**（只看语法、只审公式、只看图注等）：只做对应步骤和交付项，其余整项省略，不写 `Not assessable` 占位。
- **泛化请求**（评价这篇、审一下、投稿前自检）：走下面四步。
- **outline 对照**：只在用户明确指定 outline 文件时执行，不得猜测哪个文件是 outline。

## 1. 稿件事实表

从稿件提取，不猜：一句话主结论 / 具体空白（缺的是报道、知识、机理、实验验证还是测量能力）/ 新贡献 / 证据表（每个关键主张落在哪个图表公式实验引用）/ 比较口径（对象、参考态、条件、单位、术语）。

主结论无法从稿件稳定复述，本身就是结构问题；不替作者发明结论。

## 2. 重建实际论证

整稿或整节先做 reverse outline，每段只写 `位置 | 实际功能 | 推进的结论或证据`，检查：

- 背景是否导向一个具体空白，空白是否正好由本文方法和结果回答。
- 每段是否只有一个功能；是否有不推进主线的背景、重复结果、提前讨论。
- 后段是否依赖前段未建立的前提；已排除的解释是否无新证据地重新成为主因。
- Results / Discussion / Abstract / Conclusion 对同一结果的范围和强度是否一致。
- 按 criteria.md 章节骨架反查缺哪一环。

然后逐项建表核对（短片段只做可见范围）：

```text
图表 | 正文首次描述 | 支撑的主张 | 主线功能 | Discussion 的解释 | 状态
符号 | 首次出现 | 定义位置 | 定义 | 单位/量纲 | 作用域 | 一致性
公式 | 全部符号 | 公式前已定义 | 公式后定义 | 未定义或冲突项
Outline 节点 | 预期功能/主张/证据 | Manuscript 位置 | 状态 | 偏差
```

- **图表**：正文描述是否准确（不是无法定位的 `as shown`），趋势数值是否与图一致；图注是否首句整图功能 → 逐 panel → 颜色线型符号统计量，机理讨论不进图注；Discussion 是否解释图表对主张意味着什么，而不是重复 Results 的数字，也没有从图里读出未显示的因果；同一结论是否被多个图表无新增信息地重复支撑；关键主张是否缺落点。正文主张依赖补充材料图表时，一并纳入审计。映射不到任何主张的图表，先回查证据表是不是漏了主张，再判为候选删除或移入补充材料。
- **符号**：所有变量、参数、自定义算子、缩写、上下标都要在首次使用前或紧随公式定义，含单位、参考态、取值范围；排版差异（粗斜体、大小写、希腊字母）必须有语义；局部重定义要限定作用域。不能因"本领域常见"就算已定义，确认不了写 `Not assessable`。
- **outline**：状态用 `Matched` / `Partially matched` / `Missing from manuscript` / `Added in manuscript` / `Reordered` / `Claim drift`。片段只判其覆盖的节点范围。新增或改序不自动算错，只报实际影响主线的。

## 3. 逻辑漏洞

只报稿件中能定位的问题：结论依赖未证明的前提；同步变化被写成因果或唯一机理；未区分同样相容的替代解释；比较口径不同却放在同一结论下；个例被扩为普适；结果支持"发生了什么"但不足以支持"为什么"；摘要或结论引入正文没建立的数据、因果、意义；术语数值图号样本量前后不一致。

承载主张的表达（结果动词、因果词、限定词、意义句）按 criteria.md「证据强度对账」逐项走三步，并在报告里写出判定的证据等级。

每个问题写成可验证的 `resolution test`：补证据、补出被省略的推理、明确限制、区分替代解释，或降低断言强度。逻辑问题不能靠改写句子掩盖。

## 4. 语言审查

独立阶段，不是逻辑检查的附带抽样。整稿必须声明实际覆盖的章节范围，未覆盖全文不得声称"全文语言检查完成"。

**下面五类分别扫一遍，不在同一遍里混做**——一遍只找一类，凭印象一次过会漏。

- `Grammar` 主谓一致、冠词、单复数、时态、语态、介词、从句、平行结构、标点、数字与单位、缩写首次定义。
- `Idiomaticity` 语法成立但搭配、语序不自然；中文直译、名词堆叠、不自然被动。
- `Clarity` 指代、修饰范围、比较关系、句子重心不清；信息顺序是否已知 → 新信息。
- `Consistency` 术语、缩写、拼写、时态、连字符、图号体例（数学符号和单位归第 2 步符号账本）。
- `Preference only` 多种自然写法并存，不报成错误；模型腔命中也记这一类，写"待作者复核"，不赋 Severity。

还查段落行文：段首是否交代本段功能，句间因果转折关系是否真实存在，段尾是否有边界结论（过渡段和操作性 Methods 段不强求）。

只定位不改写。重复模式解释一次但必须列全部位置，不用"例如"隐藏未报告的问题。输出：

```text
分项判断：语法准确性 | 术语与体例一致性 | Native-like | 句间衔接 | 段落行文
问题账本：ID | 位置 | 原文 | 类型 | 诊断 | Fix route | 同类问题的其他位置
```

## 5. 维度评级

等级：`Strong` 主线清楚 / `Needs work` 可修复但实质影响可信度 / `Critical` 主结论或关键论证链尚不成立 / `Not assessable` 材料不足（不是负面评分）。不计总分，每级必须附稿件证据。

| 维度 | 核心问题 |
|---|---|
| 问题与贡献 | 问题、空白、创新点是否具体、对应且由正文支持 |
| 全文架构 | 是否沿一条主线推进，有无断点、回头路、重复 |
| 证据与逻辑 | 主张是否有可定位证据，前提是否成立，替代解释是否区分 |
| 符号与公式 | 符号是否及时定义，全文口径是否一致 |
| 图表与主线 | 图表描述和讨论是否准确并服务主线 |
| 断言边界 | 相关与因果、观察与机理、局部与普适是否区分 |
| 语法与规范 | 语法、拼写、标点、语言体例是否正确一致 |
| 语言与行文 | 搭配、句法重心、衔接和信息推进是否自然清楚 |

## 问题分级与字段

`Critical` 使主结论或关键证据链失效 / `Major` 显著削弱论证、可重复性或理解 / `Minor` 局部问题，不改变科学判断。

同一根因只建一个问题，列出多个表现位置。语言问题只进语言账本，不在「优先问题」里另立条目——除非升级为断言边界问题（如用 `demonstrate` 承载单一间接结果），此时只引语言账本 ID 和一句摘要。

```text
ID | Severity | Category | Location | Claim or original text
Diagnosis | Why it matters | Resolution test | Fix route
```

`Fix route` 是交给下一步的接口，先判断是文本问题还是科学问题：

- 文本问题（表达、结构、章节组织）→ 具体到 `p-article-polishing` 的条目，如 `自检 1 强度匹配证据`、`structure.md 章节骨架·Abstract 行`。纯语法拼写写 `直接改`。不要把本 skill 的 criteria.md 写进 Fix route。
- 科学问题（证据不足、缺对照、缺验证、缺引用）→ 作者侧动作：`补实验` / `补计算` / `补分析` / `补引用` / `作者科学决策`。不能路由给 `p-article-polishing`。
- 断言过强：现有证据够支持更弱结论 → 文本问题；必须保住原结论 → `补证据` 或 `作者科学决策`。

位置必须来自实际稿件，无法验证时写章节名、段落开头或 `location not provided`，不编造。

## 交付

泛化请求的默认交付；点名维度时未被请求的项整项省略。

1. **评价范围** — 读取内容、边界、缺失材料、主结论、空白类型、可见证据。
2. **总体判断** — 最强之处、主要瓶颈，各一句。
3. **维度评级** — `维度 | 等级 | 稿件证据 | 首要提升方向`
4. **优先问题** — Critical → Major → Minor，用上面的字段。
5. **图表与主线** / **符号与公式** / **Outline 对照** — 第 2 步的表。未指定 outline 写"未指定，不执行"。
6. **语言评价** — 第 4 步的分项判断和问题账本。
7. **值得保留** — 只列有稿件证据的具体优点。
8. **修改顺序** — 逻辑证据 → 符号公式图表 outline → 章节段落重排 → 语法体例。

没有某一级问题就写"未发现"，不凑数。交付前核一遍：每条批评都指向稿件中的主张、文本或缺失边界；事实缺失与真实缺陷已分开；每个实质问题都有可执行的 `Fix route`。
