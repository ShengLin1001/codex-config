# Research Orchestration

## 核心流程

1. 将任务拆成输入、输出和验收标准明确的独立工作单元；存在依赖的步骤保持串行。
2. 每个子任务写清数据边界、允许修改的文件、输出目录和禁止事项。
3. 先收集原始产物，再由汇总者统一术语、单位和结论层级。
4. 另设独立复核，抽查关键数值、源码语义、复现命令和失败案例。
5. 最终报告区分已验证、推断、未验证和阻塞项，并保留产物路径。

## 易踩点

- agent 自述完成不是验收证据。
- 不并行修改同一文件或依赖同一中间结果的任务。
- 不让复核者只阅读摘要；必须回到原始数据和脚本。
- 项目要求集中交付时，把 agent 产物放在指定目录而不是散落源码树。
