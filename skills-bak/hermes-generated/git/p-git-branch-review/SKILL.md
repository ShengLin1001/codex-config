# Git Branch Review

## 核心流程

1. 记录当前分支、工作区状态、目标分支、上游和共同祖先。
2. 用提交列表和三点 diff 审查目标分支的实际改动，排除缓存、生成物和无关文件。
3. 运行与改动范围匹配的最小测试；有冲突时逐文件确认语义，不做整树覆盖。
4. 经授权后执行 merge 或 rebase，并再次检查状态、日志和测试。
5. 只有用户明确要求时才 push；push 后核对远端 SHA。

## 易踩点

- 脏工作区中的原有修改属于用户，不得顺手覆盖或提交。
- Windows PowerShell 中引用 `@{u}` 时要加引号。
- merge 成功不等于功能验证成功。
